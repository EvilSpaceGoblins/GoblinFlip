# 0.7.0 implementation and verification

Implemented startup/bootstrap, bundled CallbackHandler and upstream LDB, library identifier fixes, shared AH/standalone workspace, notification/controller wiring, filters/settings, virtualized results/history/ledger, live quote/review/confirmation buttons, feature health and seven-step resumable onboarding.

Calculation fixes include preserving item-info multiple returns, carrying item level/class metadata, applying DE gross fees once, treating internal prices as illustrative/non-executable, signed/rounded displays, bounded vendor products and exact partial copper allocation. Pending transactions recover after reload; unrelated money changes never confirm a purchase. Ledger supports explicit receipt quantities, proceeds, manual entries, outcome verification and full last-disposal reversal. Schema 1 migration retains a backup; unknown newer schemas remain untouched.

Mail/merchant snapshots provide observations only. They do not prove attachment receipt or a sale, so the player records verified quantities/proceeds. Commodity buying remains disabled. Internal DE probability tables and material prices remain unverified for the target server. Reliable automatic auction-specific purchase confirmation still requires validation against the actual client; uncertain results require explicit in-game verification and Ledger resolution.

Local checks: dependency-free mock regression suite in enUS/deDE, Lua parsing, diff whitespace checks and ZIP packaging. CI is configured for Lua 5.1/5.4. The local interpreter is Lua 5.5.1; CI and in-game results have not been observed from this session.

## In-game release checklist

1. Back up GoblinFlip saved variables. Install the ZIP in a clean AddOns folder with no optional addons. Confirm login/setup, `/gf`, settings, minimap click/menu/drag/lock, and skip/resume/reload.
2. Check Health with missing, disabled and late-loaded providers. Choose Native only when APIs/events are available. Run a manual scan at the correct faction/neutral AH; verify tuple/table data against actual client returns, throttle/cooldown/error recovery and AH close/cancel.
3. Install the intended Auctionator build. Verify Get All payload/event registration, resolved vendor prices and live search freshness. Compare several whole-stack vendor calculations against actual item tooltips.
4. Inspect AH and separate-window layouts at small/large UI scales. Switch pages repeatedly, scroll past the first viewport, sort/select results, and inspect read-only history. Confirm buttons do not overflow or overlap.
5. With a deliberately small budget, test quote → review → confirm once. Verify changed offers, expiration, duplicate clicks, funds/budget/market changes and AH closure. Do not enable commodity purchases.
6. Reload with a submitted/uncertain transaction. Verify buying/reset remain blocked, then resolve only after checking the in-game outcome. Confirm successful spend is charged once and failed purchases are not charged.
7. Record partial receipt and partial disposal; compare realized profit to actual amounts. Test a full buyback reversal. Check manual entries persist. Never infer receipt merely from an item being visible in the inbox.
8. Test supported DisenchantBuddy API/skill detection separately. Confirm missing/stale/illustrative data cannot be bought and internal estimates never claim verified live material prices.
9. Test existing schema 1, malformed records and a future schema on copies of saved data. Confirm backup/preservation and no silent data-reset path.

The installable artifact is generated by `python3 scripts/package.py`; it includes the TOC files, bundled licenses and this checklist, and excludes tests and the historical audit.
